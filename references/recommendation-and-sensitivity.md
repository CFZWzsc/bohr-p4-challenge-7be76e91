# 推荐、敏感性与缺失数据

## 1. 加权评分

- 默认权重（`assets/policy.json`）：目标契合 0.25、风险 0.20、成本与时间 0.20、可行性 0.20、证据 0.15。
- case 提供 `weights` 时优先使用；缺失项用 policy 默认值补齐，再整体归一到和为 1，并在 `uncertainty` 中记录。
- 每个维度先做 min-max 归一，再乘权重。缺失维度从该候选的加权分母中剔除，同时记录 `weight_coverage`。
- `conservative_score` 把缺失维度按 0 分、权重照常计入，用于检查“缺失数据是否在替候选加分”。

排名先按 `eligible`（可行性、预算、时间窗、参数域均通过）分组，再按 `weighted_score`、`conservative_score`、候选 id 排序；不可行候选仍保留在表中。

## 2. 推荐字段

`recommendation` 包含：

- `selected` / `name` / `rationale` / `runner_up` / `margin` / `confidence`
- `decisive_factors`：首选相对次选在每个维度上的归一化差与权重，正值表示首选占优，负值表示权衡代价。
- `rejected`：每个落选候选的首要差距或不可行原因。
- `would_change_choice`：敏感性语句，直接回答“什么证据会改变选择”。
- `caveats`：缺失维度、保守分、待落实的采购/外协等。

## 3. 敏感性设计

每次运行都会做四类压力测试，结果写入 `sensitivity`：

1. **权重扰动**：每个维度权重 ×0.75 与 ×1.25，其余权重按比例重归一，记录是否换选。
2. **权重扫描**：每个维度从 0.05 扫到 0.95，步长 0.05，其余权重按比例分配，记录首次翻转的权重阈值（不含 0 与 1 的退化端点）。
3. **缺失数据压力**：对每个缺失维度分别取“最有利=1.0”和“最不利=0.0”，检查是否换选；这是“补什么数据会改变结论”的直接依据。
4. **资源降级**：依次把每个可行候选设为不可行/超预算，检查备选方案。

`sensitivity.stable` 仅表示在 ±25% 权重扰动与缺失数据压力下结论不变；权重扫描的阈值仍会写入 `flip_conditions`，用于说明更大范围改动的影响。

## 4. 缺失数据政策

- 缺失一律写 `null`，绝不填 0、均值、行业默认值或“看起来合理”的估计。
- 每个缺失单元同时写入 `missing_data`：候选、字段、原因、影响、处理方式（固定包含 `no imputation`）与定位。
- `uncertainty` 记录权重来源、单位假设、文本重合代理、缺失数量等系统性不确定性。
- 若缺失数据的最有利情形会改变选择，`would_change_choice` 必须出现对应语句，且 `confidence` 不得为 high。

## 5. 解释边界

推荐是基于给定字段、权重与约束的决策辅助，不是对科学正确性的证明。所有数字都应能由 `costs[].formula`、`time` 分项或 `scores.by_candidate.raw` 复算；无法复算的字段应在 `uncertainty` 中说明。
